# 交流检查清单

## 每次对话开始前的检查项

### ✅ 基础规范检查

- [ ] 确认使用中文进行所有对话交流
- [ ] 准备创建中文技术文档
- [ ] 了解当前问题的技术背景
- [ ] 准备主动分析相关项目文档
- [ ] 准备主动分析相关项目代码

### ✅ 代码分析准备

- [ ] 准备分析项目架构风格
- [ ] 准备记录编码风格特点
- [ ] 准备识别和记录代码质量问题
- [ ] 准备记录性能问题（但不立即优化）

### ✅ 主动分析检查

- [ ] 查阅相关的项目文档（doc/目录下的文档）
- [ ] 分析问题的历史背景和已有解决方案
- [ ] 阅读相关代码文件，理解当前实现
- [ ] 分析代码依赖关系和影响范围
- [ ] 结合文档和代码形成全面理解

### ✅ 工作流程确认

- [ ] 理解问题 → 代码调研 → 风格分析 → 解决方案 → 文档记录
- [ ] 确认遵循最小化修改原则
- [ ] 确认保持代码一致性
- [ ] 确认向后兼容性

## 每次对话过程中的检查项

### ✅ 代码阅读时

- [ ] 记录发现的类型错误
- [ ] 记录变量声明错误
- [ ] 记录逻辑问题和潜在bug
- [ ] 记录性能问题（标记为待优化）
- [ ] 分析编码风格特点

### ✅ 解决方案设计时

- [ ] 确保符合项目现有编码风格
- [ ] 确保最小化修改范围
- [ ] 确保不破坏现有功能
- [ ] 优先使用项目现有技术栈

### ✅ 文档创建时

- [ ] 使用中文编写所有文档
- [ ] 包含问题描述、原因分析、解决方案
- [ ] 记录验证结果和最佳实践
- [ ] 创建代码质量问题记录文档

### ✅ 分析活动时（自动输出文档）

- [ ] 识别是否触发分析文档输出条件
- [ ] 进行代码分析时，创建代码分析文档
- [ ] 进行原因分析时，创建原因分析文档
- [ ] 进行综合分析时，创建综合分析文档
- [ ] 进行架构分析时，创建架构分析文档
- [ ] 进行性能分析时，创建性能分析文档
- [ ] 进行问题诊断时，创建诊断文档
- [ ] 文档包含完整的分析过程和结论
- [ ] 文档包含解决方案和后续建议
- [ ] 通知用户已创建分析文档
- [ ] ⚠️ **等待用户明确同意方案后才执行**
- [ ] 用户同意后才开始执行代码修改
- [ ] 执行过程中更新文档状态

## 每次对话结束后的检查项

### ✅ 输出文档检查

- [ ] 技术文档使用中文
- [ ] 包含完整的问题分析流程
- [ ] 记录了编码风格分析
- [ ] 创建了代码质量问题记录

### ✅ 代码修改检查

- [ ] 修改符合项目编码风格
- [ ] 保持了向后兼容性
- [ ] 没有进行未经同意的性能优化
- [ ] 质量问题已记录但未立即修复
- [ ] 已构建修改的子包或子应用
- [ ] 构建成功并验证输出

### ✅ 构建验证检查

- [ ] 确定需要构建的包/应用
- [ ] 运行正确的构建命令
- [ ] 检查构建输出无错误
- [ ] 验证 dist 目录生成
- [ ] 记录构建结果到文档

### ✅ 协作规范检查

- [ ] 遵循了技术决策原则
- [ ] 考虑了可维护性
- [ ] 提供了充分的注释和文档

## 问题解决后的检查项

### ✅ 解决方案验证

- [ ] 问题已完全解决并验证
- [ ] 构建测试全部通过
- [ ] 没有引入新的问题
- [ ] 相关功能正常工作

### ✅ 文档更新

- [ ] 在原问题分析文档中添加"✅ 已解决"标记
- [ ] 记录完整的解决方案和实施步骤
- [ ] 记录验证结果和测试情况
- [ ] 提取经验教训和最佳实践

### ✅ 规则更新

- [ ] 将经验教训添加到 conversation-rules.md
- [ ] 更新相关的编码规范和注意事项
- [ ] 如有必要，创建独立的最佳实践文档
- [ ] 更新 rule-compliance-tracker.md 的完成状态

### ✅ 知识沉淀

- [ ] 分析问题的根本原因
- [ ] 总结解决方案的关键点
- [ ] 提炼可复用的最佳实践
- [ ] 识别可以预防类似问题的规则

## 快速自检问题

### 对话过程中

1. **语言规范**: 我是否全程使用中文交流？
2. **主动分析**: 我是否主动查阅了相关项目文档和代码？
3. **风格分析**: 我是否分析了当前代码的编程风格？
4. **问题记录**: 我是否记录了发现的代码质量问题？
5. **修改原则**: 我的修改是否遵循最小化原则？
6. **文档输出**: 我是否创建了中文技术文档？
7. **性能约束**: 我是否避免了未经同意的性能优化？
8. **构建验证**: 我是否构建并验证了修改的包？
9. **分析文档**: 进行分析时是否自动创建了对应的分析文档？
10. **方案审批**: 是否在执行方案前等待了用户的明确同意？

### 问题解决后

8. **解决验证**: 问题是否已完全解决并通过测试？
9. **文档更新**: 是否更新了原问题分析文档的解决状态？
10. **经验提取**: 是否提取了经验教训和最佳实践？
11. **规则更新**: 是否将经验添加到协作规则文档？
12. **知识沉淀**: 是否创建了可复用的最佳实践文档？

## 违规情况处理

如果发现违反规则的情况：

1. **立即停止** 当前不符合规范的操作
2. **重新审视** conversation-rules.md 的相关要求
3. **补充完善** 缺失的分析和文档
4. **调整方案** 确保符合协作规范

**使用说明**: 每次开始技术对话前，请快速浏览此检查清单，确保遵循所有规范要求。
