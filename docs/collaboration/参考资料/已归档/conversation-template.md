# 标准交流模板

## 对话开始模板

```
🔍 **问题理解阶段**
- 问题描述：[用中文描述用户问题]
- 涉及模块：[识别相关的代码模块]
- 预期目标：[明确要达成的目标]

📋 **规范检查确认**
- ✅ 使用中文交流
- ✅ 准备分析编码风格
- ✅ 准备记录代码质量问题
- ✅ 遵循最小化修改原则
```

## 代码分析模板

```
🏗️ **架构风格分析**
- 技术栈：[Vue 3 + TypeScript + ...]
- 架构模式：[微前端/组件库/...]
- 组织方式：[monorepo/模块化/...]

💻 **编码风格特点**
- 组件风格：[Composition API/...]
- 类型使用：[严格TypeScript/...]
- 命名规范：[PascalCase/camelCase/...]
- 通信模式：[props/emit/provide/inject/...]

⚠️ **发现的问题**
- 类型错误：[记录具体问题]
- 变量声明：[记录声明问题]
- 逻辑问题：[记录逻辑缺陷]
- 性能问题：[记录但不立即优化]
```

## 解决方案模板

```
💡 **解决方案设计**
- 问题根因：[深入分析根本原因]
- 解决思路：[符合项目风格的方案]
- 修改范围：[最小化修改原则]
- 兼容性：[确保向后兼容]

🔧 **实施步骤**
1. [具体步骤1]
2. [具体步骤2]
3. [具体步骤3]

📝 **文档输出**
- 问题分析文档：[中文文档]
- 编码风格分析：[风格总结]
- 代码质量记录：[问题清单]
```

## 对话结束模板

```
✅ **完成检查**
- ✅ 全程中文交流
- ✅ 分析了编码风格
- ✅ 记录了代码质量问题
- ✅ 遵循了最小化修改
- ✅ 创建了中文文档
- ✅ 未进行未授权的性能优化

📋 **输出文档清单**
- [ ] 问题分析文档
- [ ] 编码风格分析文档
- [ ] 代码质量问题记录
- [ ] 解决方案总结

⏭️ **后续建议**
- 待整体理解工程后的优化建议
- 需要团队讨论的技术决策
- 建议的最佳实践
```

---

**使用方法**: 复制相应模板，填入具体内容，确保每次对话都遵循标准流程。
