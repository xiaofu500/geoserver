# 文档优化流程规则

## 📋 文档信息

- **文档版本**: v1.0
- **创建时间**: 2026-01-15
- **适用项目**: SpacewareConops v3.0.1
- **参考标准**: [Documentation Workflow Best Practices 2025](https://www.meistertask.com/blog/project-documentation-best-practices-12-essential-strategies-for-2025)

## 🎯 核心原则

1. **自动输出**: 分析活动自动创建对应文档
2. **简洁高效**: 只写必要内容，避免冗余
3. **结构清晰**: 统一模板，易于查找
4. **持续更新**: 边解决边优化，保持文档时效性

## 🔄 完整流程

```mermaid
flowchart TD
    Start([触发文档需求]) --> Identify[识别文档类型]

    Identify --> Type{文档类型}

    Type -->|代码分析| CodeAnalysis[代码分析文档]
    Type -->|原因分析| RootCause[原因分析文档]
    Type -->|综合分析| Comprehensive[综合分析文档]
    Type -->|架构分析| Architecture[架构分析文档]
    Type -->|性能分析| Performance[性能分析文档]
    Type -->|问题诊断| Diagnosis[诊断文档]
    Type -->|编码总结| Summary[总结文档]

    CodeAnalysis --> Template[选择文档模板]
    RootCause --> Template
    Comprehensive --> Template
    Architecture --> Template
    Performance --> Template
    Diagnosis --> Template
    Summary --> Template

    Template --> Create[创建文档]
    Create --> Content[填充内容]

    Content --> Diagram{需要图表?}
    Diagram -->|是| AddDiagram[添加 Mermaid 图表]
    Diagram -->|否| Review

    AddDiagram --> Review[内容审查]
    Review --> Quality{质量检查}

    Quality -->|不合格| Improve[改进内容]
    Improve --> Review

    Quality -->|合格| Save[保存文档]
    Save --> Link[更新文档索引]
    Link --> End([完成])

    style Start fill:#e1f5e1
    style End fill:#e1f5e1
    style Type fill:#d1ecf1
    style Quality fill:#fff3cd
    style Save fill:#d4edda
```

## ✅ 文档质量检查清单

- ✅ 标题清晰（包含日期）

## 🎨 Mermaid 图表规范

### 架构图（graph）

```mermaid
graph TD
    A[组件A] -->|调用| B[组件B]
    B -->|返回| A

    style A fill:#e1f5e1
    style B fill:#d1ecf1
````

**使用场景**: 展示组件关系、模块结构

### 流程图（flowchart）

```mermaid
flowchart TD
    Start([开始]) --> Process[处理]
    Process --> Decision{判断}
    Decision -->|是| End([结束])
    Decision -->|否| Process

    style Start fill:#e1f5e1
    style End fill:#e1f5e1
    style Decision fill:#fff3cd
```

**使用场景**: 展示业务流程、决策逻辑

### 时序图（sequenceDiagram）

```mermaid
sequenceDiagram
    participant A as 用户
    participant B as 系统

    A->>B: 请求
    B->>B: 处理
    B-->>A: 响应
```

**使用场景**: 展示交互流程、数据流

### 类图（classDiagram）

```mermaid
classDiagram
    class Component {
        +props
        +methods()
    }

    Component <|-- SubComponent
```

**使用场景**: 展示类结构、继承关系

## 🚫 禁止事项

1. ❌ **过度详细**: 避免冗长的描述，保持简洁
2. ❌ **缺少图表**: 复杂关系必须用图表展示
3. ❌ **模板不一致**: 必须使用统一模板
4. ❌ **文件名混乱**: 必须包含日期和清晰描述
5. ❌ **提前输出总结**: 编码总结必须等待用户测试通过
6. ❌ **忽略更新**: 发现问题时必须更新相关文档
7. ❌ **缺少索引**: 新文档必须更新文档索引

## 🔄 文档生命周期

```mermaid
stateDiagram-v2
    [*] --> 创建: 触发条件
    创建 --> 审查: 内容完成
    审查 --> 改进: 质量不合格
    改进 --> 审查: 重新审查
    审查 --> 发布: 质量合格
    发布 --> 维护: 持续使用
    维护 --> 更新: 发现问题
    更新 --> 审查: 更新完成
    维护 --> 归档: 过时
    归档 --> [*]
```
