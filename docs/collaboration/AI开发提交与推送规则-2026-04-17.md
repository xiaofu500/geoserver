# AI 开发提交、推送与当日文档规则

| 项 | 内容 |

| 适用范围 | `D:\code\demo` 仓库 |
| 文档类型 | 协作规则 |

---

## 1. 规则目标

为避免出现以下问题：

1. AI 已完成开发，但代码只停留在本地工作区。
2. AI 已完成开发，但当天做过的内容没有沉淀到文档。

现统一增加固定规则：

**每次 AI 开发完成后，必须同时完成三件事：**

1. 更新当日文档
2. 提交代码
3. 推送到远程仓库

---

## 2. 触发条件

满足以下条件时，视为一次“AI 开发完成”：

1. 用户提出的本轮开发任务已实现。
2. 必要的本地验证已完成，至少包括构建或最小可用验证。
3. 没有用户明确要求“先不要提交”或“先不要推送”。

---

## 3. 当日文档规则

### 3.1 必须更新当日文档

每次 AI 开发完成后，必须把本轮开发内容总结到**当日文档**中。

总结内容至少包括：

1. 本轮改动目标
2. 实际改动内容
3. 关键文件路径
4. 验证结果
5. 仍存在的风险或后续建议

### 3.2 当日文档的优先位置

按以下优先级确定“当日文档”：

1. **优先更新当日专题文档**
   - 目录：`docs/features/<YYYYMMDD>/`
   - 适用：本轮开发明显属于某个当天主题

2. **若没有合适的专题文档，则创建或更新当日开发总结**
   - 目录：`docs/summaries/`
   - 命名：`开发总结-<主题>-<YYYY-MM-DD>.md`
   - 模板：`docs/summaries/开发总结模板-当日记录.md`

3. **若本轮属于协作/流程/规则类改动**
   - 目录：`docs/collaboration/`
   - 直接更新对应规则文档，同时仍建议补一份当日总结

### 3.3 推荐写法

建议每次追加一个新小节，而不是整篇覆盖。

推荐格式：

```md
## 2026-04-17 本轮开发记录

- 目标：
- 修改：
- 关键文件：
- 验证：
- 后续：
```

## 4. 提交与推送规则

### 4.1 必须执行的动作

当本轮开发完成后，AI 应按以下顺序执行：

1. 检查工作区改动
2. 更新当日文档
3. 仅暂存本轮相关文件
4. 按 Conventional Commits 规范创建提交
5. 推送到当前工作分支对应的远程仓库
6. 在最终回复中明确说明：
   - 更新了哪份当日文档
   - 提交号
   - 提交信息
   - 推送目标分支

### 4.2 标准流程

```bash
git status --short
git add <本轮相关代码文件> <当日文档文件>
git commit -m "<conventional commit message>"
git push origin <current-branch>
```

如果当前分支没有上游分支，则使用：

```bash
git push -u origin <current-branch>
```

---

## 5. 例外情况

以下情况不应直接推送，而应先向用户说明：

1. 远程仓库未配置
2. 当前环境无推送权限或认证失败
3. 用户明确要求只做本地修改
4. 工作区存在无法确认归属的大量混杂改动
5. 推送会覆盖用户未授权的远程历史

此时最少要完成：

1. 更新当日文档
2. 本地提交
3. 明确说明未能推送的原因
4. 给出下一步处理建议

---

## 6. 提交信息要求

提交信息继续遵循仓库现有规范：

```text
<type>(<scope>): <subject>
```

例如：

```text
feat(forest-fire-vue): refine preview fireline shaping
fix(renderer): guard ash material wind uniforms
docs(collaboration): add AI completion rules
```

---

## 7. 执行优先级

本规则优先级高于一般性的习惯流程，但低于以下用户明确指令：

1. “不要写文档”
2. “不要提交”
3. “不要推送”
4. “先给我看 diff”
5. “等我确认后再 push”

---

## 8. 最终规则

**默认情况下，只要 AI 完成一轮开发并通过必要验证，就必须执行：更新当日文档、提交本轮改动、并推送到远程仓库。**
