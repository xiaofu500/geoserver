## 💻 编码风格

### 命名规范

| 组件名    | PascalCase       | `BaseFooter`      |

| 函数名    | camelCase        | `getUserInfo`     |

### Vue 组件风格

#### 组件逻辑与业务逻辑分离

**核心原则**: 组件只负责 UI 渲染和用户交互，业务逻辑必须封装到 composables 中。

**分层职责**:

| 层级 | 位置 | 职责 |
|------|------|------|
| 组件层 | `components/` | 模板渲染、UI 状态、用户交互事件绑定 |
| 业务逻辑层 | `composables/` 或 `features/*/composables/` | 数据处理、业务规则、API 调用、状态管理 |

**目录约定**:

```
src/
├── components/          # 纯 UI 组件，不含业务逻辑
├── composables/         # 通用 composables（可跨功能复用）
│   └── cesiumHooks/     # Cesium 相关通用 hooks
└── features/            # 功能模块
    └── simulation/
        └── composables/ # 该功能的业务逻辑 composables
```

**示例 - 正确做法**:

```typescript
// ✅ composables/useXxx.ts - 封装业务逻辑
export function useRegionManager() {
  const regions = ref<Region[]>([]);
  const selectedId = ref<string | null>(null);

  // 业务逻辑：数据加载、过滤、状态管理
  const loadRegions = async () => { /* ... */ };
  const selectRegion = (id: string) => { /* ... */ };

  return { regions, selectedId, loadRegions, selectRegion };
}
```

```vue
<!-- ✅ components/RegionPanel.vue - 只负责 UI -->
<script setup lang="ts">
import { useRegionManager } from '@/features/simulation/composables/useRegionManager';

// 组件只调用 composable，不包含业务逻辑
const { regions, selectedId, loadRegions, selectRegion } = useRegionManager();
</script>
```

```vue
<!-- ❌ 错误做法 - 业务逻辑混入组件 -->
<script setup lang="ts">
const regions = ref<Region[]>([]);

// ❌ 业务逻辑不应直接写在组件中
const loadRegions = async () => {
  const data = await fetch('/api/regions');
  regions.value = data.filter(r => r.active).map(r => ({ ...r, label: r.name }));
};
</script>
```

**Composable 命名规范**:

- 通用 Cesium 操作: `useCesiumXxx` → `composables/cesiumHooks/`
- 功能业务逻辑: `useXxx` → `features/<功能>/composables/`
- 跨功能通用逻辑: `useXxx` → `composables/`

#### 组合式 API 优先

```vue
<script setup lang="ts">
import { ref, computed } from 'vue';

// 响应式数据
const count = ref<number>(0);

// 计算属性
const doubleCount = computed(() => count.value * 2);

// 方法
const increment = () => {
  count.value++;
};
</script>
```

#### 组件通信模式

**父子组件**:

```typescript
// 父组件传递 props
<ChildComponent :data="parentData" @update="handleUpdate" />

// 子组件接收 props 和 emit
const props = defineProps<{
  data: DataType;
}>();

const emit = defineEmits<{
  update: [value: string];
}>();
```

**跨组件通信**:

```typescript
// 使用事件总线
import { useEventBus } from '@spaceware/event-bus';

const eventBus = useEventBus();
eventBus.emit('eventName', data);
eventBus.on('eventName', handler);
```

**全局状态**:

```typescript

const userStore = useUserStore();
userStore.updateUser(userData);
```

### TypeScript 使用风格

#### 类型定义

```typescript
// 接口定义
interface UserInfo {
  id: string;
  name: string;
  age: number;
}

// 类型别名
type Status = 'pending' | 'success' | 'error';

// 泛型使用
function getData<T>(id: string): Promise<T> {
  return fetch(`/api/${id}`).then((res) => res.json());
}
```

#### 类型安全

```typescript
// ✅ 推荐：明确的类型声明
const user: UserInfo = {
  id: '1',
  name: 'John',
  age: 30,
};

// ❌ 避免：使用 any 类型
const data: any = getData();

// ✅ 推荐：使用 unknown 并进行类型守卫
const data: unknown = getData();
if (isUserInfo(data)) {
  console.log(data.name);
}
```

#### 响应式类型处理

```typescript
import { ref, Ref } from 'vue';

// 明确指定 ref 类型
const count = ref<number>(0);
const user = ref<UserInfo | null>(null);

// 使用 Ref 类型
function useCounter(): { count: Ref<number>; increment: () => void } {
  const count = ref(0);
  const increment = () => count.value++;
  return { count, increment };
}
```

## 📝 代码修改原则

### 1. 保持一致性

- ✅ 遵循项目现有的编码风格
- ✅ 使用相同的命名规范
- ✅ 保持相同的代码组织方式
- ✅ 使用相同的技术方案

### 2. 最小化修改

- ✅ 只修改必要的部分
- ✅ 避免大范围重构

- ✅ 保持原有结构

### 3. 向后兼容

- ✅ 不破坏现有功能

- ✅ 移除冗余代码
- ✅ 改进错误处理
- ✅ 添加必要注释

## ⚠️ 性能约束

### 核心原则

**性能问题只记录，不立即优化**

### 记录格式

```markdown
## 性能问题记录

### 问题 1: 频繁的 DOM 查询

**位置**: `src/components/Layout.vue:45`
**描述**: 在 resize 事件中频繁查询 DOM 元素
**影响**: 可能导致性能下降
**优化建议**: 使用缓存或 ResizeObserver
**状态**: 待优化（需授权）
```

### 何时可以优化

- ✅ 用户明确同意后
- ✅ 完全理解整个工程后
- ✅ 有明确的性能指标
- ✅ 有完整的测试覆盖

### 对话过程中的编码

**例外**: 对话过程中的新代码编写要性能最优

```typescript
// ✅ 推荐：使用 Map 而不是 Array.find
const userMap = new Map(users.map((u) => [u.id, u]));
const user = userMap.get(userId); // O(1)

// ❌ 避免：在对话中写低性能代码
const user = users.find((u) => u.id === userId); // O(n)
```
